# Project conventions

- Write project-authored documentation, diagrams, database schemas, and fictional examples in English.
- Preserve imported source records in their original language; do not translate or rewrite raw evidence as documentation cleanup.
- Keep documentation language separate from runtime UI localization.
- Keep code comments brief and useful to readers who know the project context but not this codebase.
- Keep product UI consistent with hoomy.dev; use `docs/design/brand.md` for brand tokens, typography, and product adaptations.

## Documentation and evidence map

Start with [the reader routes](README.md), [research questions](docs/research/README.md)
and [the agent guide](docs/guide/ask-your-agent.md). Distinguish current code behavior,
fixture checks, observed pilot results and untested hypotheses; cite the relevant
source and state limits. Use [the result template](docs/research/result-template.md)
for a proposed public experiment report.
